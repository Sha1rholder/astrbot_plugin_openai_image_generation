# Image generation instructions (Responses API)

Use `openai_image_generate_webp_responses_api` to generate and deliver lossless static WebP with OpenAI Responses API and `gpt-image-2.6-sunburst`.

## Parameters

- `prompt`: Object with required `text` and optional `images` reference indices
- (Optional) `previous_response_id`: The `response_id` saved in a successful earlier request's archive. Prefer this for further edits to an image generated by this plugin: the stored response supplies the original image context without uploading the image again. Omit or use `null` for an independent request. Never invent an ID or use a local request number or image generation call ID.
- (Optional) `size`: String in `WIDTHxHEIGHT` format such as `1536x1024`. Both dimensions must be multiples of 16 and no greater than 3840. The aspect ratio must be between 1:3 and 3:1. Total pixels must be between 655,360 and 8,294,400. Resolutions above 2560x1440 total pixels are experimental. Automatically selected if omitted.
- (Optional) `quality`: `low`, `medium`, `high`, `xhigh`, `max`. Defaults to `auto`.
- (Optional) `complexity`: `low`, `medium`, `high`. Control how much the image model plans before rendering. Lower complexity can suit focused edits, such as changing a background or a sign. Higher complexity can help with dense text, complex layouts, and relationships between objects. Higher complexity can increase latency and introduce unwanted changes, so compare results for your task. Defaults to `high`.
- (Optional) `background_transparency`: `opaque` or `transparent`. Defaults to `auto`.
- (Optional) `number_of_images`: Number of separate output images, from 1 to 5. Defaults to 1. Set this parameter for multiple images; do not specify the output count in `prompt.text`.

In most cases you should omit optional arguments as all have reasonable defaults.

## Regular image generation

```json
{"prompt":{"text":"Generate an anime girl in a maid outfit kneeling on shallow water at midnight, sobbing. She has long black hair and green eyes, with her left hand gently covering her mouth as she tries to hold back her sorrow, and a faint tear streak on her face."},"quality":"xhigh"}
```

## References and delivery

For edits to an image previously generated by this plugin, find its archived `response_id` as described below and pass it as `previous_response_id`. Set `prompt.text` to the requested changes and omit `prompt.images` unless adding new reference images. This works even when the current message has no attachments and the available reference indices are `none`; the user does not need to resend or quote the original image.

For newly supplied reference images, the instructions tool lists available indices below. Indices start at 1, with current message images first, followed by quoted images. Select up to 16 indices in `prompt.images`, in the order you describe them. These indices refer only to listed attachments, not images in earlier conversation history or archive directories. An independent text-only request needs neither `images` nor `previous_response_id`. If an earlier image has no usable response ID, ask the user to resend or quote it.

```json
{"prompt":{"text":"把图改为水彩画风","images":[1]}}
```

## Previous requests

Search the archive directory shown below with `rg -n -i -F -g request.yaml -- 'keyword' 'ARCHIVE_DIR'`. Each numbered directory contains the original arguments in `request.yaml`. The submission acknowledgement gives the exact archive path for that request. Successful generations also contain `0.webp`, `1.webp`, etc. Verify that image files exist before sending them.

After a successful Responses API generation, `request.yaml` also contains a top-level `response_id` when the provider returns one. For a follow-up edit, identify the image the user means, read its archive, and pass that top-level ID as `previous_response_id`. Each successfully generated revision can supply its own response ID for further edits; use the ID belonging to the intended version. Do not reuse `request.previous_response_id`, which points to the parent response. No previous response is selected automatically. Wait for generation to finish before reading the new ID.

```json
{"prompt":{"text":"保留主体，将背景改为雪山"},"previous_response_id":"resp_..."}
```

The plugin sends `store: true` so the provider can retain response context. Continuation requires the same endpoint and account to have access to the stored response.
