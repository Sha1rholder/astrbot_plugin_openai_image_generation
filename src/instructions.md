# OpenAI image generation instructions v0.3.0

Generate and deliver lossless static WebP with gpt-image-2.6-sunburst.

There're two tools available for image generation tasks:
- openai_image_generate_webp_responses_api (Use this by default)
- openai_image_generate_webp_image_api

They share similar parameters:
- `prompt`: A string describing the image to generate or the changes to make to an existing image. Include relevant details such as the subject, composition, style, and any constraints. For edits, specify what should change and what should remain unchanged.
- `description`: A short description of the images you expect. Automatically sent to user along with generated images. Doesn't affect image generation.
- (Optional) `reference_images`: An ordered list of attachment indices or absolute local image paths on AstrBot host. Integer indices start at 0: current message images first, in appearance order, followed by quoted images. The instructions tool lists available indices at the end. Local paths must point to readable files ending in `.jpg`, `.jpeg`, `.png`, or `.webp`. Indices and paths may be mixed, up to 16 images total. Each image must be valid PNG, JPEG or WebP and fit within the 20 MiB limit after Base64 encoding.
- (Optional) `size`: String in `WIDTHxHEIGHT` format such as `1536x1024`. Both dimensions must be multiples of 16 and no greater than 3840. The aspect ratio must be between 1:3 and 3:1. Total pixels must be between 655,360 and 8,294,400. Resolutions above 2560x1440 total pixels are experimental. Automatically selected if omitted.
- (Optional) `quality`: `low`, `medium`, `high`, `xhigh`, `max`. Defaults to `auto`.
- (Optional) `complexity`: `low`, `medium`, `high`. Control how much the image model plans before rendering. Lower complexity can suit focused edits, such as changing a background or a sign. Higher complexity can help with dense text, complex layouts, and relationships between objects. Higher complexity can increase latency and introduce unwanted changes, so compare results for your task. Defaults to `high`.
- (Optional) `background_transparency`: `opaque` or `transparent`. Defaults to `auto`.
- (Optional, Image API only) `number_of_images`: Number of separate output images, from 1 to 5. Defaults to 1. Set this parameter to generate multiple images at once. Don't specify it in `prompt`.
- (Optional, Responses API only) `previous_response_id`: The `response_id` saved in a successful earlier request's archive. Required for follow-up edits to previously generated images via Responses API.
- (Optional, Responses API only) `web_search`: Boolean, enabled by default. Set `false` to disable search explicitly for this call. You can ask Responses API to search for something before generating images. Enabling it doesn't enforce web search.

In most cases you should omit optional arguments as all have reasonable defaults. Below is a simple example for Image API.

```json
{"prompt":"Generate an anime girl in a maid outfit kneeling on shallow water at midnight, sobbing. She has long black hair and green eyes, with her left hand gently covering her mouth as she tries to hold back her sorrow, and a faint tear streak on her face.","description":"Anime gril sobbing at night","number_of_images":3}
```

For Responses API, you're instructing an LLM with image generation tools instead of directly sending prompts to image generation models. Omit `number_of_images` and instruct it in your prompt instead.

```json
{"prompt":"先搜索什么是“奶龙”，然后用它的形象生成3张富有创意的奶龙大笑图","description":"创意大笑奶龙"}
```

For image edits, select references using attachment indices or accessible local image paths, in the order you describe them. Indices refer only to listed attachments in current message, not earlier conversation history or archive directories. Local paths should refer to files readable by AstrBot process.

```json
{"prompt":"把图改为水彩画风","description":"水彩白毛红瞳少女","reference_images":[0]}
```

To find previously generated images, search the archive directory with `rg -n -i -F -g request.yaml -- 'keyword' 'ARCHIVE_DIR'`. Successful generations create numbered directory containing `request.yaml`, `0.webp`, `1.webp`, etc. `request.yaml` should contain key `response_id` if it's generated by Responses API.

To edit a specific archived image through either API, find its existing file and pass its absolute path in `reference_images`. Replace the example path below with the actual path. You can mix a current attachment and a local reference:

```json
{"prompt":"把图一人物改为图二的配色风格","description":"紫色猫娘修女","reference_images":[0,"/AstrBot/data/workspaces/Mira_FriendMessage_3190707762/0.webp"]}
```

For follow-up edits using the earlier Responses API conversation, pass `response_id` as `previous_response_id`. Each successfully generated revision can supply its own response ID for further edits; use the ID belonging to the intended version. In this case, `reference_images` becomes optional because stored responses already supply the earlier images. Use local paths instead when selecting specific output images or editing through Image API.

```json
{"prompt":"Previous image depicted Celestia from _Strinova_ incorrectly.\n\n1. Use web search to look up her appearance.\n2. Change her irises to red. Keep every other part of the existing image unchanged. Preserve pupils and eye highlights.\n\n3. Add a bow to Celestia's dress using the newly sent bow image as a reference.","description":"Celestia in Strinova with red irises","reference_images":["/AstrBot/data/workspaces/Mira_GroupMessage_647529600/images/bugui_bow_20261115_011414.jpg"],"previous_response_id":"resp_..."}
```

To utilize the functionality of Image API, you should provide more detailed descriptions compared to Responses API.

```json
{"prompt":"画一幅日系二次元哥特洛丽塔少女人设图。她身材苗条，曲线优美，仪态端庄，正面直视镜头，双手自然交叠于身前，表现出典雅、乖巧而淡漠的气质。她身着一身女仆装，头发黑长直及腰，留有整齐的空气感齐刘海，有明亮的血红色瞳孔，神情温柔。她佩戴白色褶边蕾丝女仆发箍，左右两侧装饰有精巧浅色缎带蝴蝶结；身穿深黑色古典长袖女仆连衣裙，胸前饰有黑色大蝴蝶结，中央镶嵌一枚椭圆形宝石胸针；泡泡袖配白色纽扣袖口，胸前竖褶花边，收腰白色荷叶边围裙，背后巨型缎带蝴蝶结，多层黑色花纹刺绣蓬蓬长裙，层叠白色蕾丝裙摆；裙下露出一小截白色丝袜，穿黑色玛丽珍鞋","description":"典雅洛丽塔女仆人设","size":"2560x1440","quality":"xhigh"}
```
